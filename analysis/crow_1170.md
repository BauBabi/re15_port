# Krähen-KI (Typ 0x21) in ROOM1170 — Vollvergleich Original ↔ Port

**Datum:** 2026-08-02 · **Methode:** Raw-MIPS-Disasm aus `info/Re1.5/PSX/BIN/STAGE1.BIN`
(file_off = addr − 0x80100000, KEIN 0x800-Header) via `re15_disasm.py`, RDT-Byte-Parse
(SCD + SCA) aus `re15_port/shared_assets/PSX/STAGE1/ROOM1170.RDT` / `ROOM1171.RDT`,
Port-Quelle `re15_port/engine/src/enemy_ai_common.c` (Krähen-Block ab Z. 2932) +
`scd_vm.c` (`op_sce_em_set`) + `scd_room_setup.c`. Vorwissen: `RE15_CROW_AI.md`,
`RE15_ENEMY_AI_AUDIT.md` (W4). Bekannte, bereits gefixte W4-Findings werden hier NICHT
wiederholt — nur Neues/Verbliebenes.

## Symptom

Nutzer-Report: Die Krähen auf dem Helipad (ROOM1170) verhalten sich nicht wie im
Original. Im Port greifen ALLE Krähen den Spieler an (Grapple/Strike/Dive); im Original
sind 5 von 7 Helipad-Krähen dauerhaft „disarmed" und kreisen nur.

## 1. ROOM1170/1171 — die tatsächliche Krähen-Konfiguration (RDT-Bytes)

Die bisherige Doku (RE15_CROW_AI.md: „Vorkommen: ROOM10C0/10C1/1120/1121") war
**unvollständig** — ROOM1170 und ROOM1171 haben je einen 7-Krähen-Roster, ROOM1171
zusätzlich 2 Event-Krähen.

### 1.1 ROOM1170.RDT — subScd @0x13cc, sub15 @file 0x17ca

```
0x03fe Ifel_ck  → 0x0402 Ck z=4 bit=242 (==1)          ; Intro-Zweig
    0x0406 Sce_em_set slot0 type=0x47 behav=0x40 …      ; Elliot + Cutscene-Execs
0x04ae Else_ck → 0x04b2 Ifel_ck → 0x04b6 Ck z=3 bit=125 (==1)   ; Re-Entry-Zweig
    0x04ba Sce_em_set 00 21 90 04 00 00 32 … pos=(-5400,-7200, 4810) dir= 400  kill=50
    0x04ce Sce_em_set 01 21 10 04 00 00 33 … pos=( 7320,-7200, 5280) dir=2000  kill=51
    0x04e2 Sce_em_set 02 21 10 04 00 00 34 … pos=( 1530,-7200, 1000) dir=3000  kill=52
    0x04f6 Sce_em_set 03 21 10 04 00 00 35 … pos=(-2770,-7200, -100) dir=3600  kill=53
    0x050a Sce_em_set 04 21 90 04 00 00 36 … pos=( 4750,-7200,-4200) dir= 320  kill=54
    0x051e Sce_em_set 05 21 00 04 00 00 37 … pos=(  530,-7200,-6650) dir=3550  kill=55
    0x0532 Sce_em_set 06 21 00 04 00 00 38 … pos=(-5750,-7200,-7100) dir=3300  kill=56
```

Bytes je Eintrag (Layout wie `op_sce_em_set`, scd_vm.c:2737ff): pc[1]=slot, pc[2]=0x21,
**pc[3]=behavior→grid_id (+0x9)**, pc[4]=4 (Floor-Band; PSX schreibt zusätzlich
+0x1BA=−(4·1800)=−7200, für die Krähe irrelevant, weil der Root +0x1ba jeden Tick per
room_coll überschreibt, s.u.), pc[7]=Kill-Flag-Index 50–56 (em-status-Gate), Pos/Dir LE.

**Grid-Werte der 7 Pad-Krähen: 2× 0x90, 3× 0x10, 2× 0x00.** Das ist die neue,
verhaltensentscheidende Information (ROOM10C0-Krähen hatten grid=0).

Aufruf-Kette: sub00 (`Switch work_vars[10]` = Entry-Szenario) → `Gosub 0f` (=sub15) bei
Szenario 0 und 3; sub11 (Erstbesuch-Dialog) setzt z3/125=1 + z4/242=1, sub02 (Intro-Ende)
löscht z4/242 → beim **Re-Entry** läuft der Krähen-Zweig. Der Port bildet genau das ab
(scd_room_setup.c:154-163 stampt `work_vars[10]`; Kommentar Z. 123-131 nennt den
7-Krähen-Spawn explizit).

### 1.2 ROOM1171.RDT — sub07 @file 0x16c0 (Varianten-RDT)

```
0x035c Ifel_ck → 0x0360 Ck z=3 bit=194 (==1)            ; Event-Zweig
    0x0364 Sce_em_set slot0 type=0x49 behav=0x00 … pos=(1250,-7200,-4900)
    0x0378 Sce_em_set slot1 type=0x21 behav=0x40 … pos=(-9970,-10000,-5680) dir=4000 kill=255
    0x038c Sce_em_set slot2 type=0x21 behav=0x40 … pos=(-9700, -8000,-7680) dir=0    kill=255
    0x03a0 Evt_exec ff 18 02                             ; Szene sub02
0x03a4 Else_ck → dieselben 7 Pad-Krähen wie 1170/sub15 (byte-identisch, @0x03a8-0x0420)
```

Die zwei behav-0x40-Krähen spawnen per INIT-Override direkt in **State 4 (FLIGHT-2)**
(@0x80112400-0c, s.u.) — das ist die geskriptete Krähen-Szene der Variante. Der Port lädt
Varianten über den Raum-Namen (`ROOM%04X.RDT`, room_pc.c:51) — 0x1171 erreicht sie, wenn
die Tür/Logik die Varianten-Nibble setzt (aot_common.c:374-378).

### 1.3 SCA-Gegenprobe: room_coll auf dem Pad = −7200

RDT@0x20 → coll=0xa80, 150 Zellen. An **allen 7 Spawn-Positionen** liefert die
byte-true room_coll-Semantik (Band 7..0, `(floor>>4)==b && !(u1&2) && (u0&4)`,
Rect um 200 geschrumpft, Rückgabe −(b+1)·1800; Port `re15_crow_room_coll`,
enemy_ai_common.c:3051-3066) den Wert **−7200** (Band-3-Zelle z. B.
w=15552,d=24768,x=−9632,z=−9128,u0=0xff,u1=0,floor=0x33). Damit gilt auf dem Pad
`+0x1ba == +0x1ea` (floor==perch) → Perch-Return (steer[9]→0x80115f00→sub 7) und
Landen (move[8], Clamp floor−400) sind im Port-Datenpfad erreichbar. **Kein Divergenz-
Kandidat; verifiziert korrekt.**

## 2. Original-Mechanismus — die für ROOM1170 entscheidenden Stellen (Disasm)

### 2.1 INIT 0x8011224c: `+0x1db = (grid & 0x10) ? 0 : 1`

```
801123cc: lbu v0,9(v1)        ; grid_id (+0x9)
801123d4: andi v0,v0,0x10
801123d8: beq  v0,zero,0x801123e8
801123dc: ori  v0,zero,0x1     (delay)
801123e0: j    0x801123ec
801123e4: sb   zero,475(v1)   ; grid&0x10 → +0x1db = 0  (DISARMED)
801123e8: sb   v0,475(v1)     ; sonst      +0x1db = 1  (ARMED)
```

Weitere INIT-Fakten (alle byte-verifiziert): `sb 1,0x800acc0c` @0x80112264;
+0x1b8/+0x1b9/+0x1ba/+0x93/+0x9a genullt (@0x80112268-98, +0x9a=HP=0!);
Flock-Count `jal 0x8001b768(0x21)` → `0x800aca50 = count<<4` (@0x801122b8-c0);
+0xa0/+0xa2 = Spawn-x/z (@0x801122cc/e8 — im Krähen-Overlay nie gelesen, Byte-Scan
160/162 über 0x80111a4c-0x80116400: nur diese 2 Writes); clip 0 (@0x801122e0-e8) +
**ein f314-Anim-Tick @0x80112300**; +0x78=0x801210fc (@0x80112324-2c);
+0x1d0..+0x1ec-Block genullt (@0x80112350-78); `+0x4=1` (@0x80112388);
`+0x1ea=+0x38` (@0x801123a0); `+0x38 −= 400` Lift-off (@0x801123b8);
**`grid&0x40 → +0x4=4`** (@0x80112400-0c).

### 2.2 Wer setzt +0x1db je wieder auf 1? NUR der Krähen-Tod.

Byte-Scan über den gesamten Krähen-Code (0x80111a4c-0x80116400) nach
`andi …,0xf0ff` / `ori …,0x800`:

- `@0x80112608` `andi v0,v0,0xf0ff` — der **Konsument** (ACTIVE-Tail-Re-Arm-One-Shot
  @0x801125dc-614: `aca50&0x800 && +0x1db==0 → aca50&=0xf0ff; +0x1db=1`).
- Producer ausschließlich in den DEATH-Lanes, jeweils Muster
  `aca50++; if (+0x1db != 0) aca50 = (aca50+1) & 0xf0ff | 0x800`:
  - `@0x801147fc-8024` (Death-Step-Übergang),
  - `@0x801149fc-4a20` (GIB-Lane),
  - `@0x80114c68-c90` (dritte Death-Lane).

**Konsequenz:** In STAGE1 ist der Krähen-Tod unerreichbar (bit-0x1f von 0x800b1028 wird
nur in STAGE3/5 gesetzt; Root-Promotion @0x80112050-98 zusätzlich `state==4 && grid&0x40`)
→ **die 5 ROOM1170-Krähen mit grid 0x90/0x10 bleiben im Original PERMANENT disarmed**:
sie launchen zwar (Dive-Decide prüft +0x1db NICHT), aber
- steer[9] Attack-Commit @0x8011331c-24: `lbu +0x1db; beq zero → kein Commit`,
- steer[10] @0x80113508-1c: `+0x1db==0 → sub 5`,
- steer[12/13/15/16] @0x80113c1c-2c: `+0x1db==0 → sub 14`.

Nur die 2 grid-0x00-Krähen (Slots 5/6) greifen an. Original-Bild auf dem Helipad:
**7 Krähen sitzen; bei Annäherung fliegen sie auf und kreisen; höchstens 2 attackieren.**

### 2.3 Dive-Decide 0x80112628 (steer[0-3]) — Ring per `sltiu grid,0x80`

```
801126ac: lbu v0,9(v1) ; grid          801126c0: lhu +0x1dc (grid<0x80)
801126b4: sltiu v0,v0,0x80             801126c8: sltiu v0,v0,0x1388  ; dist<5000
801126b8: beq  v0,zero,0x801126cc      801126cc: lhu +0x1dc (grid>=0x80)
                                       801126d4: sltiu v0,v0,0x2710  ; dist<10000
801126e0-e8: lh +0x1ec; slti 5400 → jal 0x80115d74(4)   ; Launch sub 4
```

**grid<0x80 → Ring 5000; grid≥0x80 → Ring 10000.** Der Port (Z. 3139) ist korrekt;
**RE15_CROW_AI.md Z. 102 dokumentiert es invertiert** (Doku-Erratum, s. D10).
Pfad C @0x80112700-38 (`aca52&1`), Pfad D @0x8011273c-88 (`aca50&0x1000` → mod-3) wie
gehabt. Für 0x90-Krähen zusätzlich: Attack-Commit → sub 10 statt 12
(@0x8011335c-68, Delay-Slot-Select `a0=0xa/0xc`), Flock-0x8000-Kommando übersprungen
(`sltiu grid,0x80` @0x801160a0-a4), Plunge-17 erlaubt (`grid != 0x80` @0x801161bc-c8).

## 4. Divergenzen

### D1 (HIGH, belegt) — Port armiert ALLE Krähen; Original: `+0x1db = (grid&0x10) ? 0 : 1`
- **Original:** @0x801123cc-e8 (Zitat §2.1). Re-Arm ausschließlich via aca50-Bit 0x800,
  dessen einzige Producer die Death-Lanes sind (@0x801147fc-8024, @0x801149fc-4a20,
  @0x80114c68-c90, jeweils zusätzlich gated auf `+0x1db!=0` der sterbenden Krähe) —
  in STAGE1 unerreichbar → ROOM1170-Krähen 0/1/2/3/4 (grid 0x90/0x10) sind im Original
  **dauerhaft passiv** (kreisen, kein Grapple/Strike/Dive-Commit, kein Schaden).
- **Port:** enemy_ai_common.c:3727 `e->crow_armed = 1;` (Kommentar behauptet byte-true
  mit Verweis „ROOM10C0 crows have grid=0" — für 1170 falsch).
- **Sichtbarer Effekt:** Port-Helipad = 7 Angreifer statt 2.
- **Fix:** `e->crow_armed = (e->grid_id & 0x10) ? 0 : 1;  /* @0x801123d4-e8 */`
  (+ Test: grid-0x10-Krähe erreicht steer[9]-Commit nie).

### D2 (MED, belegt) — Weave-Call fehlt in move[4] und move[5]
- **Original:** `jal 0x80115e24` @0x80112b60 (move[4]) und @0x80112cf8 (move[5]),
  zwischen y-Integration und pos_advance.
- **Port:** Z. 3240-3248 / 3251-3259 — kein `re15_crow_weave`.
- **Effekt:** Auffliegende Krähen banken bei Spieler-Distanz <2000 nicht (±80/Tick) —
  genau die Take-off-Phase, die man in 1170 ständig sieht.
- **Fix:** `re15_crow_weave(e);` vor `re15_crow_advance(e);` in beiden Cases.

### D3 (MED, belegt) — move[10] step1 ohne Anim-Tick
- **Original:** step1 endet mit f314 @0x801136dc-f4 (beide Klettern-Zweige und der
  In-Band-Übergang laufen in den Anim-Call).
- **Port:** Z. 3339-3346 `return` ohne `re15_crow_anim`. Da Krähen vom geteilten
  Anim-Pass ausgenommen sind, friert clip 6 während der Approach-Steigphase auf Frame 0.
- **Fix:** vor dem `return` in step1 `re15_crow_anim(e);`.

### D4 (MED, belegt) — Grab-/Strike-Schaden im Port gegated; Original unconditional
- **Original:** Grapple `hp −= 8` @0x80113e34-3c und Strike `hp −= 4` @0x801144f0-fc
  ohne +0x93-Prüfung und ohne +0x93-Write (nur der Dive-Hit prüft +0x93==0
  @0x80113ac0-cc). +0x93 wird von der (unportierten) Player-Cmd-FSM verwaltet.
- **Port:** beide über `re15_crow_hit_player` (Z. 3092-3101): `if (hit_react != 0)
  return;` + `hit_react |= 1`.
- **Effekt:** Während der Spieler nicht im Normal-State ist (z. B. von einer zweiten
  Krähe gegriffen; der Frame-Clear @0x80031964 läuft nur im Normal-Zweig), verpuffen
  Folge-Strikes im Port; im Original stapeln sie (−4/−8).
- **Fix:** In move[12]/[16] den hp-Abzug + Lethal-Broadcast direkt (ungegated) ausführen;
  das Gate + der Latch bleiben ausschließlich beim Dive-Hit (Case 11, wo `hit_react==0`
  bereits in der Commit-Bedingung steht). Den hit_react-Proxy-Latch (Ersatz für die
  cmd-FSM-Knockdown-Seite) als solchen kommentieren, falls er für den Flinch-Detektor
  gebraucht wird — aber nicht mehr den Schaden unterdrücken lassen.

### D5 (LOW, belegt) — move[0]-Timer: kein unconditional Wrap
- **Original:** @0x80112824-2c `addiu v1,a0,255; bne a0,zero,…; sb v1` — Dekrement
  IMMER (0→255), bei t==0 zusätzlich +0x1d3++.
- **Port:** Z. 3222-3223 `if (timer==0) pturn++; else timer--;` — +0x1d5 bleibt 0,
  pturn inkrementiert jeden weiteren Tick. Verhaltensneutral (steer konsumiert pturn im
  Folge-Tick und resettet +0x6→step0 schreibt den Timer neu), aber Byte-Werte von
  +0x1d5/+0x1d3 weichen ab. Dieselbe Wrap-Semantik ist in move[6]/[7]/[12]/[13]/[14]
  korrekt umgesetzt — nur move[0] weicht ab.
- **Fix:** `uint8_t t0 = e->crow_timer; e->crow_timer = (uint8_t)(t0 - 1);
  if (t0 == 0) e->crow_pturn++;`

### D6 (LOW, belegt; STAGE1-unerreichbar) — Death-Lane-Flock-Writes fehlen
- **Original:** alle drei Death-Lanes: `aca50++` und, falls die sterbende Krähe armed
  war, `aca50 = (aca50+1) & 0xf0ff | 0x800` (Re-Arm-Broadcast an die Disarmten) —
  @0x801147fc-8024 / @0x801149fc-4a20 / @0x80114c68-c90.
- **Port:** `re15_crow_death` (Z. 3627-3661) schreibt s_crow_flock nicht.
- **Relevanz:** nur STAGE3/5 bzw. `re15_crow_death_event`-Tests; für 1170 kein Effekt.
- **Fix:** in den Death-Übergängen `s_crow_flock++; if (e->crow_armed)
  s_crow_flock = (uint16_t)((s_crow_flock & 0xf0ff) | 0x800);` an den drei zitierten
  Stellen nachziehen.

### D7 (LOW/OFFEN, Write belegt) — INIT `0x800acc0c = 1` unmodelliert
