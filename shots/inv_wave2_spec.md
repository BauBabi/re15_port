FUN_800217b0(a0, a1, a2, a3) = channel CONFIG only (does not touch the level): a0 low byte = fade channel 0-3 (0x44-stride array @0x800b5458), a0 high byte = semi-trans blend mode ABR written into the channel's two DR_MODEs via SetDrawMode(tpage=abr<<5) — 0x200 => channel 0, ABR 2 = SUBTRACTIVE (back minus front) black overlay; a1 = signed s16 per-frame step (stored @+2, DAT_800b545a); a2 = 3-bit RGB enable mask (bit2=R,bit1=G,bit0=B -> 0x00/0xff mask bytes; 7 = neutral black fade); a3 = OT bucket index for the AddPrim. FUN_800216ec(ch, value, unused, rect) = KICK: if step!=0 -> level = (step<=0 ? 0x7fff : 0) and 'value' is IGNORED (so the 0x2200/0x404040 and 0x200/0x404040 literals at the inventory call sites are dead arguments); if step==0 -> level=value (static overlay hold). Ticker FUN_80021880 (per rendered frame): skip if level bit15 set; drawn brightness = level>>7 (0..0xff), rgb = brightness & masks; then level += step with u16 wrap — crossing into bit15 ends the fade; done-poll FUN_8002178c(ch) = sign bit. FRAME MATH for |step|=0x1800: ramp-up draws exactly 6 frames (level 0x0000,0x1800,0x3000,0x4800,0x6000,0x7800 -> brightness 0x00,0x30,0x60,0x90,0xc0,0xf0; next tick 0x9000 = done — full 0xff is NEVER drawn by the ramp); ramp-down draws exactly 6 frames (0x7fff,0x67ff,0x4fff,0x37ff,0x1fff,0x07ff -> 0xff,0xcf,0x9f,0x6f,0x3f,0x0f; next 0xefff = done). The port's fade_common.c (re15_fade_config/kick/tick/done) already models all of this byte-true — wave 2 only needs to issue the driver calls below.

**Open questions:**
- Name-print font page: the SPRT16 glyph prims inherit their tpage from the text-system OT-slot chain (@0x800b829c + depth*12 structures) which was not fully decoded — the glyph atlas (u=(code&0xf)*16, v=(code>>4)*16+32, clut TEX row 0 @(256,480)) is almost certainly the same TEX.TIM message font the port already replays, but the DR_MODE that precedes the chain should be dumped from the savestate prim buffers before wave 2 wires the name print.
- Visual identity of the non-ASCII name glyphs (code 0x57 in 'H?Gun Bullets' — expected '.', code 0x5b in the Medicine mixes — expected '+', code 0x08 in 'H&K MC51' — expected '&'): letters/digits byte-verify under chr=code+0x24, but these three should be confirmed by rendering the font atlas cells (v-row 0x70/0x90 area) once, or by a framebuffer capture with the cursor on id 0x15/0x27/0x13.
- Wide-pair parity after compaction: FUN_8004dadc shifts slots/cells by 1 per freed slot, which could leave a wide head at an odd slot (screen halves split across a row) or at slot%3==2 in the VRAM cache (cells not adjacent). Whether the game prevents this (e.g. the wide pair is always removed/re-inserted together, or compaction skips kind-1/2 pairs) was not traced — needs a live test (pick up wide weapon + drop/use an earlier item) before wave 2 models compaction for wide pairs.
- FUN_8004dc4c bumps DAT_800b25c8 by +2 unconditionally on wide insert, turning 'nothing equipped' 0x80 into 0x82 — downstream ==0x80 compares then fail. Byte-true as disassembled (@0x8004dc84-9c has no 0x80 guard); whether any later code renormalizes 0x82 is untraced. Port should replicate the raw behavior and live-verify equipping after a wide pickup with empty hands.
- The heal ammo-counter x for kind 0 differs between sites: LAB_80049524 init writes 0x96, but the swap-anim flow writes 0xac @0x8004b104-b11c (y 0x3a both) and the equip-anim FSM reportedly 0x96/0x35 — each wave-3 anim step must use its own site's constants; the discrepancy itself is unexplained (possibly covers the different sprite slide phases).
- FUN_80021634(1,0)/(2,0) calls in the open chain and screen init (@0x8001ca30, @0x8004957c) were not decoded (display/environment setup adjacent to the fade engine) — harmless for wave 2 but should be identified before claiming the full open chain is ported.
